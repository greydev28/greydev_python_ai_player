# Greydev's Roadmap to AI Engineering

## Stage gates (advance by evidence, not calendar)
### Gate 1 — Python fluency
You can solve new small problems with strings, loops, collections, functions, and exceptions without copying a tutorial.

### Gate 2 — Application engineering
You can build a modular CLI program, persist state safely, write tests, use Git, and debug tracebacks.

### Gate 3 — Python developer proficiency
You can independently design, implement, test, document, version, and maintain a multi-module Python application. You understand file/database persistence, errors, type hints, tests, Git branches/conflicts/recovery, and can explain your design choices. Do not rush into AI work before this gate.

### Gate 4 — Data literacy
You can inspect a dataset, clean it, visualise it, and explain what the data does and does not support.

### Gate 5 — ML fundamentals
You can compare a baseline with a trained model, select appropriate metrics, avoid leakage, and explain model limitations.

### Gate 6 — Neural networks
You can describe tensors, loss, gradients, optimisation, training/validation, overfitting, and checkpointing.

### Gate 7 — LLM application engineering
You can build an LLM/RAG feature with validation, sources, an evaluation set, privacy controls, and bounded cost.

### Gate 8 — Production readiness
You can expose an API, test failures, configure secrets, deploy, monitor, and explain rollback.

## Weekly review template
- What did I build?
- What can I now explain without notes?
- Which tests did I add?
- What bug took the longest, and what did it teach me?
- What did I read in official documentation?
- What will I build next week?
- What evidence proves I'm ready for the next stage?

## Important
"Best" is an ongoing direction, not a certificate. Aim to become unusually reliable: reason clearly, read documentation, test claims, protect users, communicate trade-offs, and finish useful projects. Use AI assistants as reviewers and tutors, not as a substitute for your own understanding.


Parts 05–14 intentionally contain no reference solutions. Treat their harder exercises as independent engineering assessments.
